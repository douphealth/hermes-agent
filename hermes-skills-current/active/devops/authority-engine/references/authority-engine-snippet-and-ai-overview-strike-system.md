## Mission
Engineer content sections so search and AI systems can extract the best possible answer from the site quickly, cleanly, and confidently.

## Core principles
1. Extraction depends on structure, not just content quality.
2. The first 1–2 sentences under a query-matching heading matter disproportionately.
3. Different query types want different extraction formats.
4. Snippet optimization and AI Overview optimization overlap, but they are not identical.
5. A page should earn extraction by being clearer than incumbents, not just shorter.
6. Over-FAQ-ing or over-formatting creates spam, not wins.

## Strike-system workflow

### Phase 1 — identify extraction targets
For each page/query, classify target opportunities:
- definition snippet
- paragraph snippet
- list snippet
- step snippet
- table snippet
- FAQ/PAA extraction
- AI Overview citation block
- voice-answer block

### Phase 2 — map query to answer format
Default pairings:
- “what is” -> definition paragraph
- “how to” -> steps
- “best / types / ways” -> list
- “vs / alternatives / compare / cost” -> table
- “why / when / can / should” -> concise paragraph + supporting bullets

### Phase 3 — heading alignment
Use headings that closely match extractable queries:
- question phrasing where natural
- direct topic phrase when the SERP prefers declarative headings
- avoid vague or decorative headings that hide the answer target

### Phase 4 — answer block design
For each target block, ensure:
- answer appears in sentence 1–2
- block is self-contained
- wording is decisive but not fake-certainty
- paragraph length fits the format
- context follows after the concise answer, not before

### Phase 5 — format-specific rules

#### Definition block
- 40–60 words
- direct “X is …” construction
- no throat-clearing

#### Paragraph snippet block
- 1–3 sentences
- direct answer first
- clarification second

#### List block
- 5–8 clean items where possible
- parallel phrasing
- no bloated bullets

#### Step block
- ordered and concrete
- each step names an action
- avoid vague process padding

#### Table block
- clear headers
- columns aligned to comparison intent
- concise cells

#### FAQ/PAA block
- only real recurring questions
- answers concise and specific
- no obvious SEO stuffing

### Phase 6 — AI Overview reinforcement
For AIO-targeted sections, also ensure:
- adjacent angles are covered: benefits, risks, alternatives, timing, cost, suitability
- at least one self-contained evidence-backed summary paragraph exists
- entities are defined cleanly
- paragraphs still make sense when quoted out of context

### Phase 7 — verification targets
A strike pass should verify:
- query-matching heading exists
- answer appears immediately below it
- extraction format matches query type
- answer block is not buried or broken by clutter
- page now contains at least one clearly superior extractable block

## Standard attack patterns

### Pattern A — snippet replacement
Use when incumbents rank but answer poorly.
- create a cleaner direct-answer block
- keep supporting context below it
- add table/list/steps if incumbent formatting is weak

### Pattern B — PAA net
Use when the page can own multiple adjacent questions.
- add 3–7 real subquestions
- answer each directly
- avoid repetitive filler

### Pattern C — AI Overview multi-angle pass
Use when the query is broad and synthesis-heavy.
- add benefits/risks/alternatives/timing/suitability sections
- keep short answer summaries near each heading
- support with concise evidence and entity clarity

### Pattern D — second-wave extraction lift
Use when the page is already strong but under-extractive.
- prepend intent note
- tighten one or more answer blocks
- improve table/list/steps formatting
- keep visible design intact

## Output contract
Report:
- extraction targets chosen
- blocks or sections added/improved
- snippet/PAA/AIO formats targeted
- where the page became more extractable
- what still limits extraction potential

## Quality bar
A good strike system makes it easy for search and AI systems to lift the right answer from the page. If the page becomes more cluttered, repetitive, or obviously spammy, it failed.
