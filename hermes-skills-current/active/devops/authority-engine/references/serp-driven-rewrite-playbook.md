# SERP-Driven Rewrite Playbook

## Purpose
Use live SERP behavior to decide what a page should become before rewriting it.

## Workflow
1. Define primary keyword, close variants, modifiers, and entity set.
2. Expand the query ladder across head terms, support questions, commercial modifiers, alternatives, cost, risks, benefits, mistakes, timing, audience variants, and geography where relevant.
3. Identify repeated ranking domains across broad, refined, and modifier queries.
4. Classify winning page types:
   - guide
   - comparison
   - alternatives
   - buyer's guide
   - FAQ
   - how-to
   - listicle
   - tool/calculator
   - hub / category / template / glossary / statistics page
5. Build a content-gap matrix:
   - what top pages cover
   - what they omit
   - what format patterns keep recurring
   - what trust elements appear near the top
   - what extractable snippet / AIO blocks they expose
   - what angle the target page can own
6. Choose rewrite mode:
   - micro-upgrade
   - additive rewrite
   - consolidation
   - full rebuild
7. Draft a section plan aligned to dominant intent plus adjacent intent angles that AI Overviews and PAA often synthesize.
8. Add trust, evidence, internal-link, and next-step CTA logic.
9. Verify live structure after publishing.

## Key rules
- Do not copy competitor structures blindly.
- Do not use random listicle fluff if the SERP rewards direct how-to content.
- Do not chase volume if the page cannot credibly satisfy the intent.
- Add missing sections only if they improve utility.
- Match the dominant page type before trying to out-write the market.
- Build explicit information gain: sharper framework, better evidence, stronger examples, cleaner comparison logic, more useful tables, stronger trust routing, or better UX.
- Every section plan should consider snippet capture, PAA coverage, and AI Overview citation potential — not just blue-link rankings.
- If the topic is trust-sensitive, define source requirements, author context, and proof burden before drafting.

## Section-planning template
Every rewrite brief should include:
- exact query and dominant intent
- page type that deserves to rank
- primary answer that must appear in the intro and/or under a matching H2
- must-cover subquestions from SERP / PAA / modifiers
- benefits, risks, alternatives, mistakes, cost, timing, suitability, and next-step sections when relevant
- extractable assets: definition block, numbered steps, checklist, comparison table, FAQ, pros/cons, scenario cards
- evidence requirements: stats, studies, official docs, original examples, expert quotes
- internal links: parent, siblings, trust, next-step CTA
- freshness signal requirements: year, update date, recent benchmark, changed market context

## Rewrite outputs should define
- new title/H1 direction
- target intro angle
- section stack
- snippet targets
- PAA / FAQ targets
- AI Overview / GEO extraction targets
- schema type
- evidence and citation burden
- internal links in and out
- next-step CTA
- what not to include because it would dilute intent

## Output contract
Report:
- dominant intent
- winning page type
- recommended rewrite mode
- must-add sections
- must-avoid filler sections
