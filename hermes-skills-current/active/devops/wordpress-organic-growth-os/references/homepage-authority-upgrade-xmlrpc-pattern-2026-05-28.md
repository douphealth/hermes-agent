# Homepage authority upgrade via XML-RPC + origin-IP workflow (2026-05-28)

Use this reference when upgrading a managed WordPress homepage for SEO/GEO/AEO authority and the normal REST API is blocked or unauthorized.

## Proven pattern
1. Load the site `STATE.md` and `SITE_PROFILE.md` first; confirm page ID and homepage role before writing.
2. Run a read-only public probe, but do not trust a single parser for H1/body rendering. For critical homepage checks, verify both raw HTML and browser DOM/visual output.
3. Create a rollback backup before any write:
   - raw current HTML/body content
   - XML-RPC page metadata
   - timestamped report directory under the site folder
4. If REST is blocked, publish via XML-RPC against the origin IP with the canonical `Host` header. Keep credentials in the local secret file only; never write secrets into artifacts.
5. For a maximum-impact homepage request, update visible body architecture, not just metadata:
   - one clear H1
   - modern hero/value proposition
   - authority router section with hub links
   - AEO/GEO answer blocks
   - trust links: About, editorial policy, review methodology, affiliate disclosure
   - money-path links: tools, checklist, affiliate guides, AI/SEO guides
   - visible disclosure where affiliate monetization is involved
6. Use inline CSS only when it is the safest production path for a small contained module and central theme/CSS edits would be riskier. Verify no raw CSS leaks publicly.
7. Purge the exact homepage URL from Cloudflare after publish.
8. Verify production output before claiming done:
   - HTTP 200
   - canonical/indexability unchanged unless deliberately changed
   - exactly one rendered H1
   - upgraded section ID present
   - no raw CSS/code leak
   - no mobile horizontal overflow
   - critical internal links return 200
   - browser/visual inspection catches overlays or legacy sections that raw checks miss
9. Update the site `STATE.md` with the new verified homepage state and known caveats.

## Caveats learned
- Public SEO `<title>` and meta description may be generated by a plugin/indexable/head layer and can remain stale even after exposed Yoast XML-RPC custom fields are patched. Treat body publish success and SERP-head remediation as separate concerns.
- A reusable read-only probe can miscount H1s on a rendered WordPress homepage if it parses the wrong surface or misses builder/rendered content. Cross-check with raw HTML and browser DOM before reporting an H1 blocker as unresolved.
- Cookie/pop-up overlays can materially affect perceived hero quality even when technical QA passes; include visual inspection for homepage work.

## Minimal final report
Lead with live URL and status, then only the evidence that matters: backup path, what changed, production QA, remaining caveats, and next highest-impact improvement.
