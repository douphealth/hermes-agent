# Max-force / visible-impact SEO delivery gates

Session lesson: when the user asks for "maximum", "superpowers", "SOTA", or reacts that edits are "almost zero", the WordPress organic-growth workflow must escalate beyond tiny metadata or paragraph tweaks. The output must be visibly meaningful on the public page while preserving factual safety and avoiding blind rewrites.

## Trigger phrases

Escalate to visible-impact or max-force mode when the user says any of:

- maximum / to the maximum extent
- superpowers / surgical superpowers
- SOTA / 100x / 10000x / 10000000x
- make the surgical SEO agent more powerful / efficient
- changes seem almost zero / too small / not enough
- outperform competitors / go harder

## Required behavior

Before claiming completion, produce public-visible proof:

- Add or substantially upgrade at least one major useful H2 section when the article is long-form and has room for expansion.
- Add multiple visible extraction assets: tables, frameworks, checklists, protocols, examples, FAQ/PAA blocks, calculators, or decision matrices.
- Improve semantic coverage and internal-link cluster routing, not only Yoast title/meta.
- Add/repair external authority references when factual claims are present.
- Measure raw content delta or clearly explain why a lower delta was safer.
- Verify cache-busted public HTML contains the new modules.
- Use browser/visual QA for major visible upgrades.
- Confirm no duplicate H1, broken canonical, raw HTML/CSS leakage, shortcode leakage, escaped anchors, or unsupported claims were introduced.

## Anti-pattern

Do not finish a max-force request with only small text edits, metadata, or invisible backend changes. That under-delivers for this user even if technically "surgical".

## Efficient implementation pattern

1. Generate a compact edit pack: current title/meta/H1/H2/H3, word count, raw flags, semantic/entity gaps, internal candidates, authority gaps, and required modules.
2. Back up raw WordPress content.
3. Apply a content-module patch rather than rewriting the whole article.
4. Update Yoast/excerpt fields when authenticated access exists.
5. Purge cache where possible.
6. Verify live page with public HTML and visual/browser checks.
