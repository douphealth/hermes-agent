# Audit Pattern Library

## Pattern 1 — Technical Ceiling
Use when content gains are capped by crawl/index/speed/canonical failures.
Action: isolate true technical blockers first, then continue only with highest-ROI content work.

## Pattern 2 — Body vs Head Split-Brain
Use when visible content is fixable by REST but metadata/schema is plugin-blocked.
Action: separate body-layer wins from head-layer blockers and queue plugin-layer remediation explicitly.

## Pattern 3 — Trust-Layer Deficit
Use when commercial pages lack visible editorial/methodology/disclosure routing.
Action: strengthen canonical trust assets and normalize links from important pages.

## Pattern 4 — Cluster Underbuild
Use when money pages lack enough support pages or internal-link reinforcement.
Action: queue support-page upgrades/creation and link normalization in waves.

## Pattern 5 — Snippet / AIO Gap
Use when pages match intent but are weak at answer extraction.
Action: add quick-answer blocks, steps, tables, FAQs, and self-contained answer sections.

## Pattern 6 — Duplicate / Cannibalization Risk
Use when multiple URLs compete for the same theme.
Action: decide canonical winner, convert weaker pages into support assets or cleanup targets.
